# P4.0-R3 — API nativa same-origin na Vercel

**Data:** 2026-10-23  
**Decisão:** D-PROD-36  
**Branch:** `cursor/fix-vercel-same-origin-api-516d`

## Sintoma

Tela **“Serviço de dados indisponível no momento.”** (`API_PROVIDER_UNAVAILABLE`)
com token em `sessionStorage` — especialmente ao abrir o app pela URL única do
deployment na Vercel (link do dashboard), não pelo alias `maike-five.vercel.app`.

## Causa

- `VITE_MAIKE_API_URL` no build apontava para `https://maike-five.vercel.app`.
- A página podia estar em outro host `*.vercel.app` do mesmo projeto.
- O navegador fazia `fetch` cross-origin; o preflight `OPTIONS` falhava (404 sem
  `Access-Control-Allow-Origin`) porque esse host não estava em `FRONTEND_ORIGINS`.
- O cliente HTTP classifica isso como indisponibilidade — não como “deslogado”.

`curl` e o alias de produção continuavam OK; só o fluxo no navegador a partir da
URL de deployment quebrava.

## Correção

Em `getNativeApiUrl()`:

1. Se env e origem são hosts `*.vercel.app` **diferentes**, usar
   `window.location.origin` (rewrites `/auth/*` → `/api/fastify` no mesmo deploy).
2. Se a env está vazia, usar a origem do navegador (build Vercel sem URL fixa).

Desenvolvimento local inalterado: `VITE_MAIKE_API_URL=http://localhost:3333` com
front em `:5173` não entra na regra Vercel (localhost não é `*.vercel.app`).
