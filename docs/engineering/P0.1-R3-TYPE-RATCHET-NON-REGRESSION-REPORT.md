## 1. Por que a CI verde da R2 não bastava

A R2 fechou quatro brechas em que o gate media o **sinal** em vez da
**propriedade**. Mas deixou a mais grave de todas em aberto — e a auditoria
externa a encontrou.

A P0.1-R2 introduziu `--rebase-contract` para permitir mudança consciente de
configuração. E, ao introduzi-la, condicionou a barreira de não regressão:

```js
if ((novos.length || aumentos.length || arquivosPiores.length) && !rebasear) {
  // falha
}
```

Depois, o fluxo de rebase gravava o baseline sem mais nenhuma verificação.
Resultado literal:

```
--rebase-contract + diagnóstico novo = baseline gravado com dívida MAIOR
```

Ou seja: **a própria operação de rebase redefinia a dívida para cima**. Uma
catraca cuja alavanca de manutenção destrava o mecanismo não é uma catraca. A CI
estava verde, mas o verde não representava a propriedade declarada.

E não era hipotético. A mesma missão que abriu a brecha caiu nela: o baseline
subiu de **2.803 para 2.808** absorvendo cinco diagnósticos do loader novo do
Google Maps, por uma nova semeadura. O relatório da R2 registrou o aumento e o
aceitou como "código novo com propósito". Isso é exatamente o que a regra proíbe.

| Bloqueador | Natureza |
|---|---|
| **R3-B1** | `--rebase-contract` desativava a não regressão |
| **R3-B2** | o baseline subiu de 2.803 para 2.808 |

Os dois são o mesmo defeito visto de dois ângulos: um no mecanismo, outro no
resultado.

## 2. R3-B1 — a barreira agora vale em todos os modos

`scripts/gates/gate-typecheck-ratchet.mjs` foi reorganizado para que a barreira
de não regressão seja uma seção única, **sem nenhuma condicional de modo**, que
roda antes de qualquer escrita:

```
1. portas fechadas (--seed)
2. contrato de configuração + cobertura
3. rodar o compilador
4. ler e validar o baseline (inclui certifiedCeiling)
5. BARREIRA DE NÃO REGRESSÃO   ← nenhuma flag desativa
6. drift de contrato
7. gravações conscientes
```

Reprova com `P01-TYPE-REGRESSION`, em execução normal, `--update` e
`--rebase-contract`, diante de:

- fingerprint novo;
- multiplicidade aumentada;
- arquivo com contagem maior;
- **total maior que o do baseline**;
- **total acima do `certifiedCeiling`**.

Os dois últimos são novos: antes o total nunca era comparado diretamente.

Quando a barreira dispara com `--rebase-contract`, a saída é explícita:

```
ATENÇÃO: --rebase-contract atualiza metadados de contrato, não o teto de qualidade.
Ele não autoriza regressão e nada foi gravado. Corrija os diagnósticos novos primeiro.
```

### Contrato de `--rebase-contract`

Serve **apenas** para atualizar conscientemente hash da configuração, cadeia
local de `extends`, versão do TypeScript, comando efetivo e metadados de
cobertura. Só grava quando:

| # | Condição |
|---|---|
| 1 | o contrato realmente mudou |
| 2 | a cobertura atual continua válida |
| 3 | nenhum diagnóstico novo surgiu |
| 4 | nenhuma multiplicidade aumentou |
| 5 | nenhum arquivo piorou |
| 6 | o total atual é menor ou igual ao teto certificado |
| 7 | o baseline permanece monotônico |

Contrato alterado com dívida **igual** ou **menor** é aceito. Com dívida
**maior**, falha e não escreve nada.

## 3. Remoção de `--seed`

`--seed` recusava execução quando o arquivo já existia. Mas apagar o baseline e
rodar `--seed` continuava sendo uma porta para redefinir a dívida — foi
exatamente assim que os 2.808 entraram na R2.

Com o baseline oficial já versionado no Git, essa porta não tem mais nenhuma
função legítima. Foi **removida**:

| Situação | Código | Comportamento |
|---|---|---|
| baseline ausente | `P01-TYPE-BASELINE-MISSING` | falha dura em todos os modos, não cria arquivo |
| `--seed` passado | `P01-TYPE-SEED-FORBIDDEN` | falha explícita, com a instrução de restaurar do Git |

Nenhuma ferramenta de bootstrap foi mantida. Fixtures de teste montam o próprio
baseline por helper (`criarBaseline`), sem passar pelo gate de produção.

## 4. `certifiedCeiling` — o teto só desce

Novo campo obrigatório no schema **3** do baseline.

| Regra | Comportamento |
|---|---|
| tipo | inteiro não negativo; ausente ou inválido reprova `P01-TYPE-BASELINE` |
| `baseline.total > teto` | `P01-TYPE-BASELINE` — baseline incoerente |
| total atual `>` teto | `P01-TYPE-REGRESSION` |
| `--update` | grava `min(teto, total atual)` |
| `--rebase-contract` | grava `min(teto, total atual)` — nunca aumenta |
| execução normal | nunca altera o teto |

Na migração desta R3 o teto de referência é **2.803**, o certificado na P0.1-R1.
Como o total final ficou em 2.802, o teto gravado é **2.802** — não se mantém
teto artificialmente maior que o total depois de uma atualização consciente.

## 5. R3-B2 — os cinco diagnósticos do Google Maps

### Antes

```
$ diff dos baselines R1 (9713c3a) → R2 (c777f6d), por fingerprint

FINGERPRINTS NOVOS: 1
  + 4x src/lib/googleMaps.js|TS2339|Property 'gm_authFailure' does not exist on type 'Window & typeof globalThis'.
MULTIPLICIDADE AUMENTADA: 1
  ^ 1 -> 2  src/lib/googleMaps.js|TS2339|Property 'google' does not exist on type 'Window & typeof globalThis'.

total 2.803 -> 2.808 · src/lib/googleMaps.js  1 -> 6
```

### A correção

Contratos de tipo reais e **locais ao arquivo**, sem `.d.ts` global, sem
`@ts-ignore`, sem `any` indiscriminado, sem tocar em cobertura:

```js
/**
 * @typedef {object} GoogleMapsNamespace
 * @property {unknown} [Map]
 * @property {unknown} [geometry]
 * @property {unknown} [drawing]
 */

/**
 * @typedef {object} GoogleMapsGlobals
 * @property {{maps?: GoogleMapsNamespace}} [google]
 * @property {(...args: unknown[]) => void} [gm_authFailure]
 */

/** @typedef {Window & typeof globalThis & GoogleMapsGlobals} GoogleMapsWindow */

const mapsWindow = () => (hasDom() ? /** @type {GoogleMapsWindow} */ (window) : null);
```

As capacidades são `unknown` de propósito: o produto só depende da **presença**
delas, e declarar o formato interno seria inventar contrato que o projeto não
tem. A conversão não silencia nada — ela declara o que o runtime realmente faz:
o SDK instala `google`, e o Google chama `gm_authFailure`. Ambos opcionais,
porque antes da carga nenhum dos dois existe.

Todos os acessos passaram a usar `mapsWindow()` e a variável local `janela`.

### Depois

| | R1 (`9713c3a`) | R2 (`c777f6d`) | R3 |
|---|---|---|---|
| `src/lib/googleMaps.js` | 1 | 6 | **0** |
| total do baseline | 2.803 | 2.808 | **2.802** |
| `certifiedCeiling` | — | — | **2.802** |

Os cinco diagnósticos introduzidos pela R2 foram removidos, **e também** o que já
existia desde a R1. Comportamento funcional do loader inalterado: os 20 testes de
`tests/smoke/googleMaps.test.js` continuam passando sem edição.

## 6. Migração do baseline

O baseline da R2 (2.808) **não** foi usado como origem. A origem confiável é o
baseline certificado da R1:

```
commit 9713c3a7b13d569e489bdd76fca6c14b4b2566b1
scripts/gates/typecheck-baseline.json  (schema 1, total 2.803)
```

A migração rodou uma única vez, fora do gate, e só gravaria se o conjunto atual
fosse subconjunto do histórico certificado. Saída real:

```
=== MIGRAÇÃO DO BASELINE — P0.1-R3 ===
origem certificada : R1 9713c3a schema 1, total 2803
medição atual      : total 2802, 150 arquivo(s), 1557 fingerprint(s)
fingerprints novos vs R1      : 0
multiplicidades aumentadas    : 0
arquivos piores vs R1         : 0
reduções vs R1                : 1
   - src/lib/googleMaps.js|TS2339|Property 'google' does not exist on type 'Window & typeof globalThis'.: 1 -> 0

GRAVADO scripts/gates/typecheck-baseline.json
  schema 3 · total 2802 · certifiedCeiling 2802
  TypeScript 5.9.3 · sha256 480480455bfedb84…
  src/lib/googleMaps.js: 0 diagnóstico(s)   (R1 tinha 1)
```

A versão do TypeScript é a mesma da R1 e da R2 (5.9.3, fixada pelo
`package-lock.json`), então não houve nenhuma diferença de mensagem de erro
legado para documentar. Se houvesse, a regra é a mesma: diferença de versão
nunca justifica dívida maior, e `--rebase-contract` continua impedindo a
regressão.

Comparação registrada em três eixos — fingerprint, arquivo e total — e reexecutada
a cada `npm run test:gates` pelo teste "o conjunto atual é subconjunto do
certificado na P0.1-R1".

### A fonte do snapshot certificado

O snapshot é uma **fixture versionada**:

```
scripts/gates/typecheck-baseline.r1-certified.json
```

Cópia verbatim de `9713c3a:scripts/gates/typecheck-baseline.json` — mesmo blob
Git, `8603e9a831d618505e5b220048aa818aa2d60a63`.

**O teste automatizado lê essa fixture, e só ela.** Não executa `git show`, não
depende da profundidade do clone e não acessa a rede.

A primeira versão do teste lia o arquivo direto do histórico, e a CI reprovou:
`actions/checkout` usa `fetch-depth: 1`, então aquele commit não existe no clone
do runner. A correção não foi afrouxar o teste nem mexer no workflow — foi tirar
a certificação dessa dependência.

A autenticidade da fixture permanece conferível **manualmente**, por quem tem o
histórico completo. É uma prova externa, fora do caminho automatizado:

```
git show 9713c3a:scripts/gates/typecheck-baseline.json \
  | diff - scripts/gates/typecheck-baseline.r1-certified.json

git hash-object scripts/gates/typecheck-baseline.r1-certified.json
# 8603e9a831d618505e5b220048aa818aa2d60a63
```

versionada. Nenhum `git show`, nenhuma dependência de profundidade de clone,
nenhum acesso à rede. Ver §6 para a autenticidade da fixture.

Suíte completa: **153 testes de gate** + 30 de smoke = **183**.

### Uma falha real de CI no caminho

A primeira execução da CI nesta missão reprovou: 152 de 153 testes passaram, e o
único que falhou foi justamente o da prova de subconjunto, por `git show` de um

e a correção está em §6.

## 12. OWNER-SECURITY-01 — pendente com o proprietário

**Inalterado e ainda aberto.** A chave do Google Maps que existia no código
permanece no **histórico Git** desta branch e da `main`. Nenhuma das missões
P0.1, R1, R2 ou R3 reescreve histórico.

O proprietário precisa:

1. **revogar** a chave antiga no console do Google Cloud;
2. **criar** uma chave nova;
3. **restringir** a chave nova por domínio (HTTP referrer) e por API
   (Maps JavaScript API, Drawing, Geometry);
4. guardar a chave nova apenas em `.env.local`, **nunca** no Git.

Tornar o repositório privado **não** torna a chave antiga segura: ela já foi
publicada.

O merge operacional da PR #1 continua **condicionado à confirmação do
proprietário** sobre essa rotação.
