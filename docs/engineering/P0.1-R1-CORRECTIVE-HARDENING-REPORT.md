## 5. Estratégia e baseline de tipos

### O problema com a medição anterior

O relatório original citava "2.788 erros" como se fosse o projeto inteiro. Não
era: o `jsconfig.json` **exclui** `src/components/ui`, `src/api` e `src/lib`, e
o `include` só pega `src/components/**/*.js` (não `.jsx`). A cobertura real era
parcial.

### Cobertura nova

`jsconfig.typecheck.json` inclui `src/**/*.{js,jsx,ts,tsx}`. As únicas exclusões
são `node_modules`, `dist`, `dist-ssr` e `coverage` — nenhuma delas é código de
produção. `src/components/ui`, `src/api` e `src/lib` **entraram** na cobertura.

Com cobertura total: **2.803 diagnósticos**.

### Contrato da catraca

```
gate:types verde  =  nenhuma regressão sobre a dívida legada versionada
gate:types verde  ≠  typecheck sem erros
```

- Fingerprint = `caminho relativo | código TS | mensagem normalizada`.
  **Linha e coluna não entram na identidade** — deslocar código não pode
  transformar dívida antiga em erro novo. Há teste específico para isso.
- Multiplicidade preservada: 1.558 fingerprints distintos somando 2.803
  diagnósticos.
- Linhas de continuação indentadas do `tsc` são dobradas no diagnóstico pai.
- Reprova em: baseline ausente, baseline malformado, versão desconhecida,
  `project` divergente do registrado, contagem inválida, soma inconsistente,
  fingerprint novo, multiplicidade aumentada, arquivo com mais erros, ou falha
  do compilador sem diagnóstico parseável.
- Execução normal **nunca** escreve. `--update` exige redução. `--seed` só
  funciona quando o baseline ainda não existe.

### Baseline

`scripts/gates/typecheck-baseline.json` — schema versão 1, com `version`,
`project`, `command`, `total` (2803), `byFile` (151 arquivos) e `fingerprints`
(1558 entradas).

A dívida bruta continua visível: `npm run typecheck:raw`.

O que **não** foi feito, deliberadamente: `@ts-nocheck`, `@ts-ignore` em massa,
`eslint-disable` amplo, `checkJs: false`, exclusão de arquivos alterados,
`|| true`, ou `process.exit(0)` após falha.

## 7. Google Maps loader

O loader anterior mantinha uma promise por conjunto de libraries e adotava
qualquer `<script>` existente que casasse com a URL — podendo pendurar a promise
quando o script já tinha terminado de carregar, e permitindo loaders concorrentes
com conjuntos de libraries diferentes.

### Contrato novo (`src/lib/googleMaps.js`)

- Conjunto **canônico único**: `drawing,geometry`. O produto preservado precisa
  de desenho (Cadastro do Mapa) e geometria (Mapa Geral), então não existem
  combinações concorrentes. Todos os 7 consumidores chamam `loadGoogleMaps()`
  sem argumento.
- Script com **ID fixo** (`maike-google-maps-sdk`); promise única de módulo.
- Retorna imediatamente quando `window.google.maps` já tem `Map`, `geometry` e
  `drawing`.
- Detecta script existente já carregado (via `dataset.loaded`) e script ainda
  carregando (anexa ao mesmo evento).
- Após falha: remove o script, limpa a promise, permite nova tentativa.
- Timeout explícito (20 s por padrão) — nunca pendura.
- Erros padronizados com `code`: `MAPS_CONFIG_MISSING`, `MAPS_SCRIPT_FAILED`,
  `MAPS_SCRIPT_TIMEOUT`, `MAPS_ENV_UNAVAILABLE`.
- Query params codificados com `URLSearchParams`; a chave nunca vai para log.
- Seguro sem DOM (SSR/testes).

Nenhuma página cria `<script>` do Maps manualmente —
`grep -rn "maps.googleapis.com" src` só encontra o loader.

**11 testes** cobrem: sem chave, primeira carga, duas chamadas simultâneas,
chamada depois de carregado, script existente carregando, script existente já
carregado, falha e retentativa, timeout, ambiente sem DOM, ausência de chave em
log, e mensagem de erro sem chave.

desde o Node 18, idêntico nas duas versões. O runner também reprova se o
diretório não existir ou se nenhum teste for encontrado, para que "nenhum teste"
nunca mais passe por verde.

Essa é exatamente a divergência local/CI que a seção 10 do enunciado pedia para
eliminar, e foi a CI que a expôs.

## 17. OWNER-SECURITY-01

**A chave do Google Maps esteve exposta no histórico Git deste repositório.**
O código não consegue revogá-la. Esta missão removeu a chave do código-fonte e
instalou o gate que impede o retorno, mas **não** reescreveu o histórico.

Ações necessárias, pelo proprietário, no console do Google Cloud:

1. **Revogar** a chave antiga. Enquanto ela existir, qualquer pessoa com acesso
   ao histórico pode usá-la.
2. **Criar uma chave nova**, distinta da anterior.
3. **Restringir** a chave nova por referenciador HTTP (domínios do produto) e
   por API (Maps JavaScript API, e só o que for necessário).
4. **Nunca** colocar a chave nova no Git. Ela vive em `.env.local`, que é
   ignorado; `.env.example` documenta o nome da variável, sem valor.

**Tornar o repositório privado não torna a chave antiga segura.** Ela já esteve
acessível; o único remédio é a revogação.

A chave antiga **não** é reproduzida neste relatório.

**Consequência para o merge:** a certificação técnica desta PR está concluída,
mas o **merge operacional fica condicionado à confirmação do proprietário sobre
a rotação da chave**. A PR permanece em draft.
