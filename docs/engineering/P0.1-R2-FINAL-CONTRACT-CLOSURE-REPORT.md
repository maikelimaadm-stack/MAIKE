## 2. Contrato de tipos (D-PROD-13)

### O buraco

`gate-typecheck-ratchet.mjs` validava apenas `base.project !== PROJECT`. Bastava
manter o nome do arquivo e trocar o conteúdo:

```json
{ "compilerOptions": { "checkJs": false }, "include": [] }
```

Os 2.803 diagnósticos virariam zero, `compareMultisets` veria só reduções, e a
catraca ficaria **verde** — celebrando uma melhora que não aconteceu. Excluir
`src/lib`, `src/api` ou `src/components/ui` teria o mesmo efeito, mais discreto.

### O que passou a ser gravado e validado

Baseline `scripts/gates/typecheck-baseline.json`, schema **versão 2**:

| Campo | Valor atual |
|---|---|
| `projectPath` | `jsconfig.typecheck.json` |
| `projectSha256` | `480480455bfedb84…` |
| `effectiveCommand` | `tsc -p ./jsconfig.typecheck.json --pretty false --noEmit` |
| `typescriptVersion` | `5.9.3` |
| `coverageContract` | `checkJs`, `include`, `exclude`, `files`, invariantes e arquivos da cadeia |
| `total` | 2.808 |
| `byFile` | 151 arquivos |
| `fingerprints` | 1.559 fingerprints distintos |

O hash usa **representação canônica**: JSONC sem comentários, sem vírgula final,
chaves de objeto ordenadas recursivamente, arrays na ordem original. A cadeia de
`extends` local entra recursivamente, sempre por caminho **relativo ao
repositório** — o hash não muda conforme onde o clone está. `extends` de pacote
entra como especificador, e a cobertura efetiva não pode depender dele.

### Cobertura validada mecanicamente

Não por comparação de texto: cada invariante é testado com **caminhos-sonda**
contra o glob real do `include`/`exclude`, na raiz e em profundidade.

Exigido:

- `checkJs: true`;
- `include` presente e não vazio;
- cobrir `src/**/*.js`, `src/**/*.jsx`, `src/**/*.ts`, `src/**/*.tsx`;
- não excluir `src/components/ui`, `src/api`, `src/lib`, `src/services`;
- exclusões apenas em `node_modules`, `dist`, `dist-ssr`, `coverage` e fixtures
  fora de `src/`.

### Códigos e flags

| Código | Quando |
|---|---|
| `P01-TYPE-CONTRACT` | a configuração **atual** viola a cobertura obrigatória |
| `P01-TYPE-CONFIG-DRIFT` | caminho, hash, comando ou cobertura divergem do baseline |
| `P01-TYPE-VERSION-DRIFT` | a versão do TypeScript mudou |

`--update` continua sendo só para diagnósticos: exige redução e ausência de
regressão. Mudança consciente de configuração ou de compilador usa
`--rebase-contract`, uma flag separada — que **também** valida a cobertura antes
de gravar. Reduzir cobertura não passa nem por lá.

## 4. Scanner de segredos (D-PROD-14)

### O buraco

```js
linhas.forEach((linha, i) => {
  if (MASKED.test(linha)) return;   // <- antes de qualquer regra
  ...
});
```

`MASKED` inclui `process\.env` e `import\.meta\.env`. Logo, esta linha **passava**:

```js
const key = import.meta.env.VITE_GOOGLE_MAPS_API_KEY || "AIza…chave-real…";
```

Que é exatamente o padrão que a missão P0.1 tinha acabado de remover de oito
arquivos do produto. O mesmo valia para `SUA_CHAVE`, `EXAMPLE`, `PLACEHOLDER` e
`REDACTED` em qualquer posição da linha.

### A correção

Cada detector declara qual grupo do match é o **valor**. A avaliação de máscara
olha só para esse valor, um match por vez.

| Linha | Antes | Agora |
|---|---|---|
| `import.meta.env.K \|\| "AIza…real…"` | passava | **reprova** |
| `process.env.T \|\| "ghp_…real…"` | passava | **reprova** |
| `"SUA_CHAVE"` + `"ghp_…real…"` na mesma linha | passava | **reprova** |
| `API_KEY = "…real…"; // EXAMPLE` | passava | **reprova** |
| chave real dentro de `.env.example` | reprovava | **reprova** |
| `import.meta.env.VITE_GOOGLE_MAPS_API_KEY` sem fallback | passava | passa |
| `VITE_GOOGLE_MAPS_API_KEY=SUA_CHAVE` | passava | passa |
| `` `${config.googleMapsKey}` `` | passava | passa |

Nove casos novos em `scripts/tests/gates/secrets.test.mjs`, incluindo dois que
verificam que a saída **não contém** o valor.

### O gate endurecido reprovou o próprio repositório

Na primeira execução completa, `no-secrets` falhou com:

```
- [P01-SECRET-HARDCODED] scripts/tests/gates/secrets.test.mjs:157 — Segredo atribuído diretamente
```

Uma fixture do próprio teste estava escrita como literal em arquivo versionado,
protegida pelo comentário `// EXAMPLE` — exatamente o bypass sendo corrigido. A
fixture passou a ser construída em tempo de execução. O achado ficou registrado
em vez de silenciado: é a prova de que a regra nova morde.

## 5. Google Maps (D-PROD-16)

### O buraco

```js
function onLoad() { succeed(); }               // sem verificar nada
if (existing.dataset.loaded === 'true') { succeed(); return; }
```

O produto declarava "mapa pronto" com `window.google` inexistente. Pior: a
promise resolvida ficava em `loadPromise`, então **toda** chamada seguinte
herdava o falso sucesso, sem retentativa possível. Havia um teste — *"não fica
pendurado quando o script já existe e já terminou de carregar"* — que
formalizava esse comportamento com `dataset.loaded = 'true'` e sem SDK nenhum.
Ele foi corrigido.

### O contrato agora

Só resolve com:

```
google.maps.Map  ∧  google.maps.geometry  ∧  google.maps.drawing
```

Depois do `load`, o loader observa as capacidades em intervalo curto até o
timeout total — o SDK pode montar os namespaces depois do evento. Se seguir
incompleto: rejeita com `MAPS_SDK_INCOMPLETE`, remove o script, limpa
`loadPromise`, permite retentativa.

Regras adicionais:

- `dataset.loaded` é pista, nunca prova;
- script com o ID correto e URL fora de
  `https://maps.googleapis.com/maps/api/js` é inválido;
- URL sem `drawing` **e** `geometry` nas libraries é inválida;
- `window.gm_authFailure` derruba a carga, encadeia e restaura o handler
  anterior;
- a chave nunca entra em log nem em mensagem de erro.

| Código | Situação |
|---|---|
| `MAPS_CONFIG_MISSING` | variável de ambiente ausente |
| `MAPS_SCRIPT_FAILED` | rede, URL inesperada, libraries incompletas, `gm_authFailure` |
| `MAPS_SCRIPT_TIMEOUT` | o script nunca respondeu |
| `MAPS_SDK_INCOMPLETE` | **novo** — carregou sem as capacidades |
| `MAPS_ENV_UNAVAILABLE` | ambiente sem DOM |

Treze casos obrigatórios cobertos em `tests/smoke/googleMaps.test.js`: load sem
SDK, `dataset.loaded` sem SDK, `dataset.loaded` com SDK completo, só `Map`,
`Map` + `geometry` sem `drawing`, SDK completo com atraso, incompleto até o
timeout, sucesso falso fora do cache, retentativa, `gm_authFailure`, URL
inesperada, libraries incompletas, simultaneidade e ausência da chave em log e
erro.

## 6. Parser de functions (D-PROD-15)

### O buraco

```js
for (const m of body.matchAll(/^ {2}([A-Za-z_][A-Za-z0-9_]*)\s*:\s*\[/gm)) {
```

Exatamente dois espaços, sem aspas. Quatro espaços, tabulação, `'Safra':` ou o
objeto em uma linha só — nada disso era visto. Uma entidade fora do manifesto
passaria pelo gate por causa de indentação.

### A correção

Análise sobre a **AST do TypeScript** (`ts.createSourceFile`). Formato deixa de
importar: 2 espaços, 4 espaços, tabulação, aspas simples, aspas duplas, uma
linha só, vírgula final, comentários, valor multilinha e CRLF foram todos
testados, cada um com uma chave-fonte fora do manifesto, e **todos reprovam**.

Acesso computado com valor não literal passa a reprovar como não verificável:

```
P01-SCOPE-FUNCTION-DYNAMIC-UNVERIFIABLE
```

Vale para `entities[nome]` e `functions.invoke(nome)`. O gate não pode afirmar
fechamento sobre um nome que só existe em tempo de execução.

### Consequência real na function preservada

`syncEntityReferences` fazia isso em três lugares:

```ts
const entityApi = base44.asServiceRole.entities?.[entityName];
```

Com a regra nova, a própria function do produto reprovava — e isso está certo: o
gate não conseguia provar nada sobre aquele acesso. A correção não foi
enfraquecer o gate, foi tornar o código verificável:

```ts
function buildEntityRegistry(base44) {
  const entities = base44.asServiceRole.entities;
  return { AreaPastagem: entities?.AreaPastagem, /* … 14 no total … */ };
}

function resolveEntityApi(base44, entityName) {
  if (!Object.prototype.hasOwnProperty.call(registry, entityName)) return null;
  return registry[entityName] || null;
}
```

As 14 entidades são exatamente a união das chaves-fonte e dos destinos de
`PROPAGATION_RULES`. Cada uma aparece como acesso literal `entities.X`, que o
gate confere contra o manifesto. O nome dinâmico passa a indexar o mapa local,
cujo domínio está visível no código. Comportamento preservado: nome desconhecido
devolve nulo, como o `?.[]` fazia; `if (!entityApi)` trata os dois casos igual.

`entry.ts`: 523 → 568 linhas.

## 11. OWNER-SECURITY-01 — pendente com o proprietário

**Inalterado e ainda aberto.** A chave do Google Maps que existia no código
permanece no **histórico Git** desta branch e da `main`. Esta missão não
reescreve histórico.

O proprietário precisa:

1. **revogar** a chave antiga no console do Google Cloud;
2. **criar** uma chave nova;
3. **restringir** a chave nova por domínio (HTTP referrer) e por API
   (Maps JavaScript API, Drawing, Geometry);
4. guardar a chave nova apenas em `.env.local`, **nunca** no Git.

Tornar o repositório privado **não** torna a chave antiga segura: ela já foi
publicada.

O merge operacional da PR #1 continua **condicionado à confirmação do
proprietário** sobre essa rotação. A certificação técnica desta missão não
substitui essa confirmação.
